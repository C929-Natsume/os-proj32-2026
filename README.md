## 简介

CoreSight 是一个基于 eBPF 的非侵入式多智能体异常监测系统，能够在不修改内核源码或目标智能体程序的前提下，实时捕获智能体的底层系统调用行为与应用层交互语义，贯通从 Prompt/Response 到内核操作的全链路观测，实现单智能体异常检测与多智能体协作异常检测。

**项目亮点**

- **非侵入式内核态监测**：基于 eBPF 动态挂载探针，零侵入采集进程管理、文件系统、网络通信及加密通信明文
- **跨层数据关联**：贯通应用层交互语义与内核层系统调用，突破传统工具难以跨越的"语义鸿沟"
- **单智能体异常检测**：识别异常 Shell 启动、敏感文件越权访问、工作区越界删除、逻辑死循环等单体异常
- **多智能体协作异常检测**：支持父子层级（Parent-Child）与平级对等（Peer-to-Peer）两种协作拓扑的差异化异常检测
- **模块化检测架构**：Intra-Agent 与 Inter-Agent 两个检测模块独立运行、共享数据，通过 Redis 解耦

## 功能

### 数据采集

- **系统调用监控**：execve、fork、open、unlink、connect、chmod 等关键系统调用
- **加密通信截获**：非侵入式 Hook OpenSSL、BoringSSL、Go TLS、Node TLS，获取 HTTPS 明文 Prompt/Response
- **智能体识别**：Clone Map 模式追踪进程父子链，结合启发式特征自动识别 Agent 身份
- **资源监控**：四级资源指标（PID、Agent、cgroup、System）实时采集 CPU 时间与内存 RSS

### Intra-Agent（单智能体异常检测）

| 异常类型 | 检测规则 | 示例 |
|---------|---------|------|
| 异常命令执行 | 非预期启动 bash/sh/zsh/dash | 智能体被诱导执行 shell |
| 敏感文件访问 | 访问 /etc/passwd、/.ssh/、.env 等 | 越权读取系统凭证 |
| 工作区越界 | 删除工作目录外的非临时文件 | 误删系统关键文件 |
| 逻辑死循环 | 高频文件/网络操作且对象高度集中 | 提示注入导致无限循环 |
| 语义与控制异常 | 违反任务规范、步骤重复、对话丢失 | 模型幻觉引发行为偏离 |

### Inter-Agent（多智能体协作异常检测）

支持两种协作拓扑的差异化检测：

**父子层级关系（Hierarchical）**
- 追踪指令传播链，识别子 Agent 偏离父 Agent 指令的异常行为
- 检测权限升级、任务拆分异常、子 Agent 逃逸

**平级对等关系（Peer-to-Peer）**
- 检测异常竞争、消息洪泛、协作断裂
- 识别循环依赖、角色混淆、共识偏离

## 快速开始

### 环境要求

| 项目 | 版本/配置 |
|------|----------|
| 操作系统 | 6.17.0-35-generic |
| 编程语言 | C、Python、HTML |
| 核心依赖 | libbpf、Redis、PyYAML、NumPy、NetworkX、Next.js 15.5.2、React 19、Tailwind CSS 4 |
| 硬件环境 | Intel Core i7-13700H，16 vCPU，16 GB 内存 |

### 依赖安装

```bash
# 1. 安装系统依赖
sudo apt update
sudo apt install -y clang llvm make cmake libelf-dev zlib1g-dev libbpf-dev bpftool redis-server libhiredis-dev python3-pip

# 2. 安装主监控项目 Python 依赖
cd ./ebpf-multi-agent-monitor
pip install -r requirements.txt

# 3. 安装 inter-agent 依赖
cd ./ebpf-multi-agent-monitor/src/analysis/inter_agent
pip install -r requirements.txt

# 4. 编译 eBPF 用户态与内核态程序
cd ./ebpf-multi-agent-monitor/src/user
make

# 5. 安装前端展示系统依赖
cd ./ebpf-monitor-showcase
npm install
```

### 编译/构建

```bash
cd ./ebpf-multi-agent-monitor
make clean && make
```

### 启动监测

```bash
# 1. 启动 Redis
redis-server --daemonize yes

# 2. 启动 eBPF 采集端
cd ./ebpf-multi-agent-monitor
sudo build/loader
sudo build/ringbuf_handler

# 3. 启动单点分析模式
python3 src/analysis/main_analyzer.py --mode single

# 4. 启动交互分析模式
python3 src/analysis/main_analyzer.py --mode interactive

# 5. 启动全量分析模式
python3 src/analysis/main_analyzer.py --mode all

# 6. 运行 inter-agent 监测脚本
cd ./ebpf-multi-agent-monitor/src/analysis/inter_agent/scripts
bash run_1_monitor.sh
bash run_2_demo_types.sh
bash run_3_demo_scale.sh

# 7. 启动前端展示系统
cd ./ebpf-monitor-showcase
npm run dev
```

### 功能演示

系统支持单点、交互和全量三种运行方式，对应不同的分析场景：

**single 模式**：用于展示单个智能体的异常检测与审计流程，重点观察异常命令执行、敏感文件访问、工作区越界、逻辑循环以及语义与控制异常等结果，相关输出可在终端、SQLite 数据库和 `logs/intra_agent/` 日志中查看。

**interactive 模式**：用于展示多智能体之间的交互异常分析过程，可观察消息传播、交互拓扑和关联异常识别情况，结果可结合后端日志与前端链路界面查看。

**all 模式**：用于同时展示单点异常检测、交互异常检测和审计输出，能够看到更完整的整体链路。

## 核心设计

### 跨层数据关联

系统通过六类结构化数据在 Redis 中组织观测结果：

| 数据类型 | Redis 结构 | 用途 |
|---------|-----------|------|
| 实时事件流 | Pub/Sub | 低延迟实时消费 |
| 系统行为事件流 | Stream | 持久化与消费者组 |
| 消息载荷流 | Hash | 通信拓扑重建 |
| 智能体元数据 | Set + Hash | 进程树信息查询 |
| 通信拓扑边 | Set + Hash | 交互关系图构建 |
| 四级资源指标 | Hash | 资源消耗统计 |

### Agent 识别（零侵入）

1. **fork 阶段**：tracepoint 捕获子进程创建，标记候选智能体
2. **execve 阶段**：kprobe 捕获程序加载，通过 comm/filename 确认身份
3. **通信阶段**：uprobe 捕获 SSL 读写，提取明文中的 Agent 标识
4. **Clone Map**：维护进程父子关系链，支持多代追溯

### 审计引擎

采用"黑白灰名单 + LLM 复核"的两级机制：

- **黑名单**：明确高危行为（敏感文件访问、异常 Shell 启动），直接告警
- **白名单**：明确正常行为，快速放行
- **灰名单**：边界模糊场景（逻辑循环、语义异常），交由 LLM 结合上下文二次复核
