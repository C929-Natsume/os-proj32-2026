### 一、网络异常检测
监测智能体与外界（LLM API、其他服务）通信中的异常模式。
- **高频/高代价 API 调用**：短时内发起远超出正常对话频次的 HTTPS 请求，导致资源浪费或成本激增。
- **数据泄露与非法外联**：Agent 连接非白名单内网 IP/域名，或主动向外部传输敏感信息（如通过 POST 携带密钥）。
- **加密流量异常模式**：利用 uprobe 解密后，发现请求内容包含 prompt 注入痕迹、可疑指令或超长无意义重复文本。
- **SSL/TLS 握手异常**：频繁短连接、证书验证失败重试，暗示中间人攻击或配置错误。

### 二、文件系统异常检测
聚焦智能体对本地文件系统的操作，尤其关注越界与破坏性行为。
- **敏感文件越权访问**：读取或修改 `/etc/shadow`、`~/.ssh/id_rsa`、系统配置文件等，超出智能体预设工作区。
- **异常删除/写入**：在工作区外执行 `unlink`、`rename`，或覆盖关键系统二进制、日志文件。
- **无意义 I/O 风暴**：对临时文件或同一路径进行高频读写（如每秒千次），却无实质内容更新，常与逻辑死循环伴生。
- **路径遍历攻击**：利用 `../` 等模式试图逃逸沙箱，访问上级或系统目录。

### 三、进程与执行异常检测
关注智能体进程的创建、执行行为及父子关系变化。
- **非预期 Shell 启动**：Agent 进程树中突然出现 `execve("/bin/sh")` 或 `bash`、`python -c` 等解释器，极可能由提示注入诱导命令执行。
- **进程链异常**：智能体执行不相关的系统命令（如 `wget`、`curl` 下载脚本并执行），或 fork 出大量僵尸进程。
- **权限提升尝试**：调用 `setuid`、`capset` 等系统调用，或通过 `sudo` 执行命令，试图打破最小权限限制。

### 四、内存与 CPU 资源异常检测
监控智能体运行时的资源占用模式，识别滥用与死循环。
- **CPU 死锁/空转**：Agent 单进程 CPU 使用率持续 > 85%，且系统调用序列显示陷入无进展循环（如重复处理相同 Prompt 而不产生有效输出）。
- **内存泄漏**：内存占用随时间单调增长，伴随频繁的 `mmap`/`brk` 调用，却无相应释放（`munmap`），最终可能导致 OOM。
- **异常资源争抢**：多个 Agent 同时抢占大量内存或 CPU 核，导致系统抖动，可结合调度延迟 eBPF 探针检测。

### 五、应用层语义逻辑异常
这是突破“语义鸿沟”的核心大类，通过关联 Prompt/Response 与底层操作，识别高层意图驱动下的深层异常。
- **幻觉诱导死循环**：捕获到的 Prompt 与 Response 构成无意义反馈环（如模型反复建议“继续操作”），伴随重复文件读写，系统调用序列无实际进展。
- **提示注入导致高危操作**：直接从 Prompt 中解析出“删除所有文件”“执行 sudo reboot”等指令，并与后续系统调用严格匹配，建立因果链。
- **多智能体协作冲突**：Agent A 的 Response 污染 Agent B 的上下文，或两个 Agent 同时修改同一文件导致数据竞争，通过关联通信内容与文件锁/写入事件判定。
- **功能滥用**：利用 Agent 设计缺陷进行超范围任务，如智能编码工具被大量用于挖矿脚本生成，结合网络连接与进程执行综合判定。
